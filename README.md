# Сервис управления рассылками

Учебный проект на Django: сервис для управления email-рассылками.

## Возможности

- Управление получателями (CRUD)
- Управление сообщениями (CRUD)
- Управление рассылками (CRUD)
- Ручной запуск рассылки
- Логи попыток отправки
- Регистрация и аутентификация (вход по email)
- Восстановление пароля
- Роли: пользователь и менеджер
- Статистика по рассылкам
- Кеширование (Redis)

## Технологии

- Python 3.13
- Django 6.1
- PostgreSQL
- Redis
- Poetry
- Bootstrap 5 (CDN)

## Установка

1. Клонировать репозиторий:
    git clone https://github.com/ваш-логин/название-репозитория.git
    cd название-репозитория

2. Установить зависимости:
    poetry install

3. Создать базу данных в PostgreSQL (например, coursework).

4. Настроить подключение к БД в config/settings.py.

5. Применить миграции:
    poetry run python manage.py migrate

6. Создать суперпользователя:
    poetry run python manage.py createsuperuser

7. Запустить Redis (в отдельном терминале):
    redis-server

8. Запустить сервер:
    poetry run python manage.py runserver

Сайт доступен по адресу: http://127.0.0.1:8000/

## Структура проекта

coursework/

## Роли

- Пользователь — управляет только своими получателями, сообщениями и рассылками.
- Менеджер — состоит в группе «Менеджеры». Видит все объекты, может блокировать пользователей и отключать рассылки.

## Отправка писем

По умолчанию используется консольный бэкенд: письма выводятся в терминал, где запущен сервер. Настроено в settings.py:

MAILERS = {
    "default": {
        "BACKEND": "django.core.mail.backends.console.EmailBackend",
    },
}

Для реальной отправки замените бэкенд на SMTP и укажите настройки почтового сервера.

## Кеширование

Используется Redis. Настроено в settings.py в разделе CACHES. Кешируются:
- главная страница (cache_page на 15 минут);
- список рассылок (cache.get/set с ключом по ID пользователя).

## Примечания

- Redis должен быть запущен постоянно, пока используется кеш.
- Для тестирования писем используйте консольный бэкенд.
